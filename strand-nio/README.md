# strand-nio

`strand-core`를 JDK NIO 소켓 위에서 구동하는 전송 모듈이다. Java 8 기준이며 외부 의존성이 없다.

## 지원하는 전송

TCP(과 TLS)만 지원한다. **WebSocket은 지원하지 않는다.** 빠뜨린 기능이 아니라 의도한 범위다. Java 8 기준에서는 JDK의 `java.net.http.WebSocket`을 쓸 수 없고, 지원하려면 RFC 6455(핸드셰이크·프레이밍·마스킹·Close)를 직접 구현해야 하기 때문이다. 근거와 대안은 [ADR 0007](../docs/adr/0007-WebSocket은-strand-netty만-지원한다.md)에 있다. WebSocket이 필요하면 `strand-netty`를 쓴다.


## 실행과 순서

클라이언트와 서버는 앱이 준 실행기를 사용자 코드 실행에 사용하며, 실행기를 직접 종료하지 않는다. 실행기는 호출 스레드에서 작업을 바로 실행하지 않아야 한다. 인증 검사, 연결 팩터리, 요청 핸들러와 관찰자 콜백은 연결별로 한 번에 하나씩 제출된 순서대로 실행된다. 콜백이 비동기 작업을 시작해 반환하면 다음 콜백은 그 비동기 작업의 완료를 기다리지 않는다.

각 연결에는 전송 스레드가 하나 있다. 연결 상태, core 사건 처리, 통로 읽기와 쓰기는 이 스레드가 소유한다. 앱 스레드에서 호출한 요청·종료 명령은 연결에 전달되어 이 순서 흐름에서 처리된다. 통로의 깨움과 닫기는 다른 스레드에서도 호출할 수 있다.

클라이언트의 연결 성공은 보안 설정, HELLO 교환, 연결 인증과 핸들러 등록이 끝난 뒤에만 완료된다. 서버는 같은 준비가 끝나기 전에 받은 요청을 애플리케이션에 넘기지 않고, 준비가 성공하면 도착한 순서대로 전달한다. 준비에 실패하면 보관한 요청은 연결과 함께 끝난다.

core가 낸 사건은 전송 스레드가 받은 순서대로 처리한다. 응답 결과가 확정되면 해당 요청의 결과를 먼저 보존하고, 연결 종료 알림은 남은 결과와 종료 원인을 보존하고 소켓·TLS 엔진·선택기를 정리한 뒤 완료한다. 핸들러나 관찰자 콜백의 반환은 연결 종료 알림 완료의 전제가 아니다.

출력은 core가 낸 순서대로 통로에 기록한다. 부분 쓰기가 생기면 그 출력이 끝나기 전에 다음 출력과 섞지 않는다. TLS 통로는 평문을 암호문으로 감싼 순서를 그대로 보낸다. core가 연결 종료를 지시하면 남은 출력을 먼저 통로에 넘긴 다음 보내는 쪽을 닫는다. 연결이 끝나면 닫기 전에 전송 계층이 보유한 출력과 본문 바이트 예약을 정리한다.

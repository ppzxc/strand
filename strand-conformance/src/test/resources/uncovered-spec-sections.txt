# 규범 문장(MUST, SHOULD)이 있지만 적합성 벡터로 확인할 수 없는 규격 절. 형식: `절번호 사유`.
# 목록에 있는 절을 벡터가 가리키기 시작하면 SpecCoverageTest가 실패한다. 그때 이 줄을 지운다.
1.2.1 WebSocket 하위 프로토콜 `strand`는 WebSocket 핸드셰이크의 헤더 규칙이라 엔드포인트의 입출력(바이트와 메시지)으로 관측할 수 없다
6.1 채널 요구(기밀성·무결성·서버 인증, TLS 1.3, ALPN `strand`)는 전송 계층 아래의 성질이라 엔드포인트의 입출력으로 관측할 수 없다
3.5.1 SHOULD 동작이라 따르지 않아도 규격 위반이 아니므로 벡터로 단언하지 않는다. 돌려보내지 않은 요청은 상대에게 결과 모름으로 남는다
3.4.1 유휴 간격은 로컬 설정이고 SHOULD 동작이라, 규격이 간격 값을 정하지 않으며 벡터 설정(config)에도 유휴 간격이 없다
4.4.1 요청 기한은 로컬 설정이고 MAY로 쓰는 기능이라 벡터 설정(config)에 기한을 정하는 항목이 없다. 벡터 형식에 요청 기한 설정을 더하면 벡터를 쓴다
3.6 SHOULD 동작이라 따르지 않아도 규격 위반이 아니므로 벡터로 단언하지 않는다. 전송 계층에 쓰는 순서는 벡터의 입출력 형식으로 관측할 수 없다

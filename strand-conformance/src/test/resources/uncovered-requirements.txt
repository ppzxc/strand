# 벡터로 확인하지 않는 MUST·MUST NOT 요구사항. 형식: `req-… 범주 사유`(한 줄에 식별자 하나).
# 관측불가: 엔드포인트의 입출력(바이트와 메시지)으로 볼 수 없다. 형식미지원: 벡터 형식에 필요한 입력·비교 필드·이벤트가 없다.
# 벡터가 요구사항을 가리키기 시작하면 SpecCoverageTest가 실패한다. 그때 이 줄을 지운다. SHOULD·SHOULD NOT은 올리지 않는다.
#
# 관측불가: 1.2.1절 WebSocket 하위 프로토콜. WebSocket 핸드셰이크의 헤더 규칙이라 바이트와 메시지로 관측할 수 없다.
req-ws-subprotocol-client-offer 관측불가 `Sec-WebSocket-Protocol: strand`는 WebSocket 핸드셰이크 헤더라 엔드포인트의 입출력(바이트와 메시지)으로 관측할 수 없다
req-ws-subprotocol-server-reject 관측불가 서버가 하위 프로토콜 없는 WebSocket 연결을 수락하지 않는 것은 핸드셰이크 단계의 동작이라 입출력으로 관측할 수 없다
# 관측불가: 6.1절 채널 요구. 전송 계층 아래의 성질이다.
req-security-channel-required 관측불가 기밀성·무결성·서버 인증을 제공하는 채널은 전송 계층 아래의 성질이라 엔드포인트의 입출력으로 관측할 수 없다
req-security-bcp195 관측불가 TLS가 BCP 195를 따르는지는 TLS 계층의 설정이라 엔드포인트의 입출력으로 관측할 수 없다
req-security-tls-hostname-verify 관측불가 서버 인증서 호스트 이름 검증은 TLS 핸드셰이크 안의 동작이라 입출력으로 관측할 수 없다
req-security-tls-no-early-data 관측불가 0-RTT를 쓰지 않는 것은 TLS 핸드셰이크 안의 동작이라 입출력으로 관측할 수 없다
req-security-tls-no-renegotiation 관측불가 TLS 사후 인증과 재협상을 쓰지 않는 것은 TLS 계층의 동작이라 입출력으로 관측할 수 없다
req-security-tls-no-plaintext-fallback 관측불가 TLS 협상 실패 때 평문으로 바꾸지 않는 것은 전송 계층 연결의 동작이라 벡터의 입출력 모델로 관측할 수 없다
req-security-alpn-client-offer 관측불가 ALPN 식별자 `strand` 제시는 TLS 핸드셰이크 안의 동작이라 입출력으로 관측할 수 없다
req-security-alpn-server-reject 관측불가 ALPN을 제시하지 않은 연결의 거부는 TLS 핸드셰이크 안의 동작이라 입출력으로 관측할 수 없다
# 형식미지원: 보내지 않는 행동을 유발하는 API 입력을 결과로 표현할 방법이 없다.
req-reset-close-only-code-forbidden 형식미지원 CLOSE 전용 error_code를 RESET에 싣고 싶어지는 상황을 만드는 입력이 형식에 없어, 구현이 그 코드를 쓰지 않는다는 것을 단언할 수 없다
req-backpressure-no-refuse-after-start 형식미지원 처리를 시작한 요청을 로컬 사유(과부하 등)로 거절하고 싶어지는 상황을 만드는 입력이 형식에 없어 거절하지 않는다는 것을 단언할 수 없다
req-hello-peer-frame-size-limit 형식미지원 상대가 알린 max_frame_size를 넘는 프레임을 호출 API에 요청했을 때 구현은 보내지 않지만, 로컬 예외나 이벤트를 벡터 결과로 표현할 수 없다
req-close-end-certainty-partial-disconnect-first 형식미지원 쓰기를 시작했지만 넘기지 못한 요청은 NIO 실행 경로에서 부분 쓰기(write_limit_bytes) 뒤 취소로만 끝낼 수 있어, 끊김이 먼저인 벡터를 만들 수 없다. core Endpoint 테스트가 고정한다 (#372, #383)
req-close-end-certainty-partial-own-end-first 형식미지원 쓰기를 시작했지만 넘기지 못한 요청은 NIO 실행 경로에서 부분 쓰기(write_limit_bytes) 뒤 취소로만 끝낼 수 있어, 내 쪽 종료가 먼저인 벡터를 만들 수 없다. core Endpoint 테스트(EndpointOutputProgressTest)가 고정한다 (#372, #383)
# 형식미지원: 1.2절 WebSocket Ping·Pong. WebSocket 계층의 제어 프레임이라 벡터 형식 2에 입력·출력 항목이 없다.
req-ws-ping-pong-not-liveness 형식미지원 WebSocket Ping·Pong은 WebSocket 계층의 제어 프레임이라 벡터 형식에 입력·출력 항목이 없다. strand-netty의 WebSocket 테스트(NettyWebSocketCloseTest)가 확인한다 (#411)
# 형식미지원: 크기 초과 프레임과 넘기지 못한 유휴 PING.
req-hello-oversize-request-local-fail 형식미지원 상대의 max_frame_size를 넘는 요청을 호출 API에 냈을 때의 로컬 실패는 벡터 결과로 표현할 수 없다(req-hello-peer-frame-size-limit과 같은 사유) (core 테스트로 고정: #384, EndpointTest.oversizeRequestDoesNotConsumeATicket)
req-hello-oversize-auth-close-silent 형식미지원 클라이언트 AUTH가 상대 max_frame_size를 넘는 상황을 만드는 입력이 벡터 형식에 없다 (core 테스트로 고정: #384, EndpointTest.clientClosesLocallyWithoutAuthOrCloseWhenItsAuthExceedsThePeerMaxFrameSize)
req-setup-unsent-idle-ping-close 형식미지원 유휴 PING 간격을 정하는 설정(8.2절)과, 출력을 여러 단계에 걸쳐 계속 막고 바이트 단위 진행만 보고하는 입력(`hold_output`은 다음 단계까지만 보류한다)이 벡터 형식에 없다. core Endpoint 테스트(EndpointUnsentIdlePingTest)와 공개 API 통합 테스트로 확인한다 (#375)

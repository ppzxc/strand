# 규격 작성 규칙

`docs/specification/STRAND_SPECIFICATION.md`를 고칠 때 따르는 규칙이다. 구현자는 규격만 읽고 구현할 수 있어야 한다.

## 규칙

- **규칙은 한 절에서만 정의한다.** 다른 곳에서 필요하면 절 번호로 가리킨다.
- **설계 근거는 본문에 두지 않는다.** "왜 이렇게 했나"는 이슈와 git 기록, 결정이 어렵고 맥락 없이는 의아한 것은 `docs/adr/`에 둔다. 구현자의 실수를 막는 안내는 근거가 아니라 `> 비규범 주석`으로 쓴다.
- **인용하지 않는 각주는 두지 않는다.** 본문을 고쳐 각주를 인용하는 곳이 없어지면 7절의 정의도 함께 지운다.
- **확장 기능은 양쪽이 기능 비트를 켠 연결에서만 쓴다.** 이전 버전이 모르고 지나치면 잘못 동작하는 기능이 대상이다. 모르는 항목을 건너뛰어도 되는 확장 영역의 선택 항목(2.4절)은 해당하지 않는다.
- **용어 정의의 정본은 규격 1.3절이다.**

## 각주 표기법

인용은 GFM 표준 각주 표기법을 쓴다. 본문에서는 영문 식별자 태그로 인용하고(예: `[^RFC2119]`), 정의는 7절에 모은다(예: `[^RFC2119]: RFC 2119, ...`). 태그는 IETF RFC의 관례를 따라 `RFC` 뒤에 번호를 붙이거나 대문자와 하이픈으로 쓴다.

7절에는 구현할 때 반드시 필요한 규범 참조만 둔다. 설계할 때 참고하거나 비교한 문서는 두지 않는다.
